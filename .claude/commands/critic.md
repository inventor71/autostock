목표: 지금 이 세션에서 만들고 있는 것을 **격리된 컨텍스트의 `critic` 서브에이전트**로 적대적 검토받고, 유효한 지적을 현재 세션 작업물에 반영한다. (이건 prompt injection이나 별도 `claude` 프로세스가 아니다 — Claude Code 서브에이전트는 독립 컨텍스트에서 돌고 최종 메시지를 이 세션으로 자동 반환한다.)

검토 대상: **$ARGUMENTS**
- 비어 있으면, 지금 작업 중인 산출물/변경을 대상으로 한다(최근 작성·수정한 문서, `git status`/`git diff`의 변경 파일).

다음 순서로 진행하라:

1. **대상·맥락 확정.** `$ARGUMENTS`(또는 현재 작업물)에서 검토할 **구체 파일/디렉터리 경로**를 정한다. 필요하면 `git status`로 변경 파일을 본다. 지금 무엇을, 왜 만들고 있는지 1–2문장으로 요약하라 — 서브에이전트는 이 세션 히스토리를 **못 보므로** 맥락을 직접 줘야 한다.

2. **`critic` 서브에이전트 스폰(Task, `subagent_type: critic`).** 프롬프트를 self-contained 하게 구성하라:
   - 한 줄 맥락: "AI-DLC로 〈무엇〉을 설계/구현 중이다."
   - 검토할 **정확한 파일 경로**(서브에이전트가 직접 읽도록) + 대조할 **실제 코드 위치 힌트**(예: 관련 모듈/함수).
   - 지시: "**사람이 문서만 읽으면 놓치기 쉬운 버그·설계 미스를 특히** 찾아라. 문서의 단정(‘안전’·‘즉시’·‘레이스 불가’·‘자동 해제’·‘멱등’ 등)을 **실제 코드로 검증**하고 `path:line` 인용하라. 심각도(HIGH/MEDIUM/LOW)로 분류하고, 가장 중요한 1–2개를 먼저 짚어라. 칭찬·요약 말고 실행 가능한 지적만."
   - (선택) 사용자가 지정한 특정 관심 영역이 있으면 강조.

3. **반환된 지적을 현 세션에 반영.** 서브에이전트 결과를 받으면:
   - 사용자에게 핵심 지적을 **요약 제시**한다(결과는 사용자에게 직접 안 보임).
   - 각 지적을 **코드로 교차 확인**한다 — 맹신 금지(서브에이전트도 틀릴 수 있다).
   - 유효한 것을 분류: **엔지니어링 보강**(바로 반영) vs **사용자 결정이 필요한 정책 분기**(질문으로 확인).
   - **큰 변경 전에는 사용자에게 확인**한다.

주의: `critic` 서브에이전트는 read-only(Read/Grep/Glob/Bash)이며 코드를 수정하지 않는다 — 반영은 이 세션(메인)이 한다.

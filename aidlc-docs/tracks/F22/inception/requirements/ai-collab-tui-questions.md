# AI 협업 TUI 개선 — 요구사항 확인 질문 (F22)

현재 시스템은 AI 에이전트(research/intraday/EOD/wake 턴)가 풍부한 데이터를 생산하고
daemon이 이를 `snapshot.json`(5초), `monitor.json`(10초), `events.jsonl` 등으로 이미 퍼블리시하고 있습니다.
그러나 TUI(opencode 포크 콘솔)에는 이 데이터를 보여주는 전용 패널이 전혀 없어서,
운영자는 CLI 명령이나 파일 직접 열기로만 AI 활동을 확인할 수 있습니다.

아래 질문에 답해주시면 어떤 협업 UX를 어떻게 구축할지 설계의 방향을 잡겠습니다.

---

## Question 1
가장 핵심적인 "AI 협업" 기능은 무엇이라고 생각하시나요? 이 트랙에서 반드시 구현해야 할 것을 골라주세요. (복수 선택 가능)

A) **에이전트 턴 타임라인** — 오늘의 research/intraday/wake/eod 턴을 시간순으로 보여주고, 각 턴의 모델·비용·결정 수·소요시간을 표시
B) **Decision Feed (결정 피드)** — 에이전트가 내린 결정(BUY/SELL/HOLD/ADJUST_STOP)을 실시간으로 스트리밍, 심볼·신뢰도·가격·이유 스니펫 포함
C) **Approval Queue (승인 대기열)** — PendingApproval 목록을 보여주고, 인라인 approve/reject 버튼으로 즉시 조작
D) **에이전트 추론 뷰어 (Reasoning Trace)** — 각 턴의 사고 과정(thinking + tool calls + 결과)을 TUI 안에서 바로 확인 (현재는 `agent_trace.py` CLI만 가능)
E) **포지션 논거 뷰어 (Thesis Viewer)** — 심볼 클릭 → 해당 `positions/SYMBOL.md` 파일을 사이드 패널/모달로 열어 AI의 판단 근거 확인
X) 기타 (아래 [Answer]: 뒤에 설명해주세요)

[Answer]: A, B, D, E

## Question 2
현재 콘솔 레이아웃에서 AI 협업 정보를 어디에 표시하고 싶으신가요?

A) **기존 사이드바 확장** — 현재 프로젝트/워크스페이스/세션 사이드바에 새로운 섹션(탭 또는 접이식 블록)을 추가
B) **별도의 전용 패널** — 메인 채팅 영역 옆이나 아래에 AI 활동 전용 패널을 상시 표시 (분할 뷰)
C) **모달/오버레이 방식** — 평소에는 숨겨두고, 단축키나 클릭으로 AI 상태 대시보드를 팝업
D) **전용 뷰 모드** — 채팅 뷰와 AI 대시보드 뷰를 탭/키보드 단축키로 전환 (두 가지 모드)
X) 기타 (아래 [Answer]: 뒤에 설명해주세요)

[Answer]: B + D.  메인 채팅 상단에 AI 활동 상시 표시 (대신 기본적으로는 타임라인만 보여주되 o----o----x---- 식의 (더 이쁘게. 마커도 informative, 디자인도 개선여지) maker(turn) 별 type/health을 표시. 마우스를 타임라인 위 각 턴위에 호버링 했을때 상세 정보를 오버레이로 띄우기(decision feed, reasoning). 포지션 논거는 나타나는 심볼에 호버링했을때 오버레이로 띄우기)

## Question 3
운영자가 AI와 "협업"한다는 것이 구체적으로 어떤 상호작용을 의미하나요? 현재 부족한 부분을 골라주세요.

A) **AI 결정을 수동 검토 후 승인/거부** — 에이전트가 제안하면 사람이 최종 결정 (현재 PendingApproval 있지만 UI 없음)
B) **실시간 지시 (Directive) 관리** — 상시 지시사항을 TUI에서 추가/편집/삭제, 에이전트 프롬프트에 즉시 반영
C) **AI에게 질문하고 답변 받기** — 에이전트가 남긴 질문(`agent_questions.jsonl`)을 보고 답변하거나, 운영자가 역으로 질문
D) **AI 판단 근거 실시간 모니터링** — 현재 턴 진행 상황(어떤 도구 호출 중인지, 무엇을 분석 중인지)을 라이브로 추적
X) 기타 (아래 [Answer]: 뒤에 설명해주세요)

[Answer]: D. Q-1의 기능들이 현재 빠져있어서 편한 모니터링이 부족.

## Question 4
에이전트 추론 뷰어(reasoning trace)의 깊이는 어느 수준이 적당한가요?

A) **요약 수준** — 턴당 1-2문장 요약 + 결정 목록만 (monitor.json의 기존 데이터 활용, 별도 파싱 불필요)
B) **중간 수준** — 턴의 주요 판단 단계(시장 분석 → 종목 평가 → 결정)를 구조화된 스텝으로 표시, tool call 결과 축약
C) **상세 수준** — `agent_trace.py`와 동등한 전체 추론 과정(thinking blocks, tool calls + 결과, 최종 텍스트)을 TUI에 내장
D) **지금은 불필요** — 추론 뷰어는 이 트랙의 범위 밖, CLI(`agent_trace.py`)로 충분
X) 기타 (아래 [Answer]: 뒤에 설명해주세요)

[Answer]: A. 다만 직접 턴에 대한 상세 질문을 요청하면 보여줄 수 있어야 함. (턴 마다 고유 ID 부여해서 쉽게 질문 가능하도록)

## Question 5
이 트랙의 범위에 대해 — v1에서 구현할 범위와 향후로 미룰 범위를 어떻게 정할까요?

A) **최소 MVP** — 핵심 1-2개 기능만 (예: Decision Feed + Approval Queue) 빠르게 구현하고 사용해보면서 확장
B) **균형잡힌 v1** — 핵심 기능 3-4개를 묶어 한 번에 의미있는 협업 경험을 제공 (턴 타임라인 + 결정 피드 + 승인 대기열 + directive 관리)
C) **포괄적 구현** — Q1에서 선택한 모든 기능을 이 트랙에서 전부 구현
X) 기타 (아래 [Answer]: 뒤에 설명해주세요)

[Answer]: C

## Question 6
AI 활동 알림(notification)은 어떻게 처리하고 싶으신가요?

A) **수동 확인** — 운영자가 직접 AI 패널을 열어 확인 (push 알림 없음)
B) **인라인 알림** — 중요 이벤트(새 결정, 승인 대기, 긴급 이벤트) 시 TUI에 배너/토스트 표시
C) **뱃지+소리** — 사이드바 아이콘에 뱃지 카운트 + 선택적으로 알림음
D) **외부 알림 연동** — TUI 내 알림 + 추가로 모바일/데스크톱 push notification (PushNotification 도구 활용)
X) 기타 (아래 [Answer]: 뒤에 설명해주세요)

[Answer]: A. 기본적으로 메인 채팅 상단에 띄워서 있어 문제 없음

## Question 7
데이터 업데이트 주기에 대해 — 현재 snapshot은 5초, monitor는 10초 간격입니다. AI 협업 UI의 반응성을 어떻게 원하시나요?

A) **현재 유지** — snapshot 5초 / monitor 10초 폴링이면 충분, 추가 인프라 불필요
B) **폴링 간격 단축** — snapshot 2초 / monitor 5초로 줄여 더 반응적인 UI (daemon 부하 약간 증가)
C) **이벤트 기반 (push)** — 상태 변경 시에만 이벤트를 보내는 방식으로 전환 (daemon/channel 리팩토링 필요)
X) 기타 (아래 [Answer]: 뒤에 설명해주세요)

[Answer]: A. 반응성 향상은 다른 이번 스코프를 벗어남. 한다면 추후 다른 트랙으로 진행

## Question 8
TUI 구현 기술 관련 — opencode 포크 콘솔(TypeScript/Ink)에서 새 컴포넌트를 어떻게 추가할까요?

A) **기존 사이드바 컴포넌트 패턴 따르기** — `sidebar-items.tsx` / `sidebar-workspace.tsx` 스타일로 React/Ink 컴포넌트 추가
B) **새 패키지(모듈) 분리** — `packages/tui-trading/` 같은 별도 패키지를 추가해 AI 협업 UI를 독립 모듈로 관리
C) **MCP 도구 확장 위주** — TUI 변경은 최소화하고, 기존 대화형 인터페이스에서 MCP 도구(steer_read 등)의 출력 포맷만 개선
X) 기타 (아래 [Answer]: 뒤에 설명해주세요)

[Answer]: B. 구현 량이 많으니 별도 패키지가 낫지 않을까? Q-2 참고. 타임라인뷰/overlay 설계도 따로 해야 할듯. (marker overlay는 턴에 대해서 작동, symbol overlay는 SYM에 대해서 작동. sym overlay는 사이드바 심볼과 같이 심볼에 대해서 다 작동하면 좋음)

## Question 9
이 트랙은 서브모듈(`operator-console/cli`, opencode 포크)을 수정해야 합니다. 서브모듈 브랜칭은 어떻게 할까요?

X) 기타 (아래 [Answer]: 뒤에 설명해주세요)

[Answer]: A

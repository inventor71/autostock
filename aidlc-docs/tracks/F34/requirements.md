# F34 — 요구사항 분석 (Requirements Analysis, minimal)

> Track: F34 · Phase: INCEPTION · Depth: **Minimal** (요청이 명확·범위 작음·UI 표현 변경)
> Single writer = F34 worktree session. 상위 `aidlc-state.md`는 레지스트리 행만.

## 1. 의도 분석 (Intent)
타임라인 top bar에서 시장 구간 라벨 `PRE` / `OPEN` / `AFT` 글자를, 그 위치에 찍히는
turn/intervention **마커가 가려서** 라벨을 읽기 어렵다. 라벨이 항상 또렷하게 보이도록
**라벨을 마커보다 위 레이어로** 올린다. 단, 라벨 글자 뒤에 숨은 마커도 **클릭은 유지**한다.

목표 레이어(위→아래): **(라벨 글자 + 투명 배경) > (마커) > (타임라인 배경/밴드)**.

## 2. 근본 원인 (코드 확인)
`packages/tui-trading/src/components/timeline-bar.tsx`의 `MarkerRow`는 페인트 순서가:
1. 높이 앵커(공백) → 2. 구간 밴드 `bandText`(여기에 `PRE/OPEN/AFT` 라벨이 대시와 함께 들어감)
→ 3. 시장 경계 `│` → 4. **turn 마커** → 5. intervention 마커 → 6. now `┃`.

마커(4·5)가 밴드(2)보다 **나중에** 그려져, 라벨 글자 칸 위에 마커가 오면 글자를 덮는다
(예: 개장 시각의 첫 마커가 `OPEN`의 `O`를 가림). 이것이 사용자가 본 현상.

## 3. 프레임워크 제약 (검증: `@opentui/core@0.2.16`)
- 마우스 디스패치는 네이티브 `checkHit(x,y)`로 **그 칸의 최상단(=가장 나중에 그려진) 렌더러블**
  하나를 찾고, 이벤트는 `Renderable.processMouseEvent` → **부모로 버블**(형제로는 안 감).
- `Renderable`에 `pointerEvents:none` / click-through 류 플래그 **없음**.
- ⇒ "라벨 박스를 마커 위에 그냥 얹기"만 하면, 그 칸 클릭이 **라벨 박스로 가서** 부모(`MarkerRow`)
  로 버블 → **밑의 마커 핸들러는 호출 안 됨**. 즉 *클릭 유지* 요구를 깨뜨림.
- 따라서 라벨 글자 뒤 마커 클릭을 살리려면 **클릭 포워딩**이 필요: 라벨 오버레이가 받은 클릭의
  x좌표 → 그 칸에 있는 마커/intervention을 찾아 해당 핸들러를 대신 호출.

## 3.1 구현 설계 (critic 적대 검토 반영, `@opentui/core@0.2.16` 교차확인)
검토 결과 두 핵심 가정(투명배경 합성 가능 / 포워딩 필요·충분)은 **코드로 확인됨**. 단, 검토가
지적한 함정을 피하도록 아래로 **확정**한다.
1. **밴드 = 대시 전용**: `bandText`에서 라벨 글자를 **빼고** `─`만 렌더(라벨의 단일 출처를
   오버레이로 일원화 → 이중 페인트/halo 제거). 밴드 배경색·구간 정체성은 그대로.
2. **라벨 오버레이 = 글자 칸 1셀 단위 박스**(넓은 박스/행 핸들러 금지). `PRE/OPEN/AFT`의 각
   글자마다 `position=absolute left={col}` 1셀 박스를 **투명 배경**(`bg` 미설정 — 마커와 동일
   하게 밴드 배경이 비침)으로, 마커/인터벤션 레이어 **뒤(=나중)에** 그림.
   - 각 셀 박스는 자신의 `col`을 **렌더 시점에 이미 앎** → 클릭 시 `evt.x`(스크린 전역 좌표,
     [HIGH]#1)에 **의존하지 않고** `col`로 마커를 찾는다. 팝업 앵커만 기존과 동일하게
     `evt.x ?? col` 전달(현행 동작과 일치).
   - 그 `col`에 마커/인터벤션이 있으면(`props.layout.markers`/`.interventions`를 **클릭 시점에
     live 조회**, offscreen 클램프 포함 `m.x === col`) 해당 `onMarkerClick`/`onInterventionClick`
     호출. 없으면 핸들러 미부착(무해 통과).
   - 라벨에 안 겹치는 마커 칸은 오버레이가 **건드리지 않음** → 기존 마커 박스가 최상단 = 기존
     핸들러 그대로(FR-4 회귀 없음, [HIGH]#2 blast-radius 회피).
3. **레이어가 위로 올라가는 것은 (투명배경) 텍스트 하나뿐**(사용자 확정 2026-06-01).
   사용자 불만은 `PRE/OPEN/AFT` 텍스트가 가려지는 것뿐이고 `│` 바는 가려져도 무방.
   - **최종 z-order(아래→위):** 밴드 배경(대시) → `│` 경계 → 마커/인터벤션 → now `┃` → **텍스트(최상단)**.
   - 즉 마커·커서는 **기존처럼 `│` 위에 그대로** 둔다(`│`를 마커 위로 올리지 않음 — 회귀 금지).
   - 텍스트는 마커뿐 아니라 now `┃`보다도 **위**다 → 같은 1셀에서 텍스트가 always 보임(불만 해소).
     (앞 초안의 "now `┃`를 라벨 위 유지"는 **철회**.) 경계 `│`(x0)와 `OPEN`의 `O`(x0+1)는
     다른 셀이라 어차피 충돌 없음.

## 4. 기능 요구사항 (FR)
- **FR-1** 라벨 글자(`PRE`/`OPEN`/`AFT`)는 **최상단**(turn/intervention 마커 + now `┃` 커서보다
  위)에 렌더링되어, 그 어떤 요소도 라벨 글자를 절대 덮지 않는다. (`│` 경계 바는 라벨 글자 칸과
  겹치지 않으므로 해당 없음.)
- **FR-2** 라벨 글자 칸의 **배경은 투명**(밑의 밴드 배경/색이 그대로 비침). 글자 자체는 기존
  라벨 색(`phaseColor`)·기존 텍스트(`phaseShort`) 유지 — 시각적 라벨 정체성 불변.
- **FR-3** 라벨 글자에 가려진 마커도 **클릭 가능**: 그 칸을 클릭하면 밑에 있던 마커/intervention의
  팝업이 기존과 동일하게 열린다(`onMarkerClick` / `onInterventionClick`).
- **FR-4** 라벨에 안 가려진(겹치지 않는) 마커의 클릭/렌더 동작은 **기존 그대로** 회귀 없이 유지.
- **FR-5** now 인디케이터(`┃`/`▼`), 경계선 `│`, 오프스크린 화살표(`‹`/`›`), 날짜 네비 등 다른
  타임라인 요소의 동작/외형은 변경하지 않는다.

## 5. 비기능 / 제약 (NFR·Constraints)
- 신규 런타임 의존성 **0** (기존 solid-js + @opentui로 충분).
- 변경 범위 = 서브모듈 `operator-console/cli`의 `timeline-bar.tsx` 1개 컴포넌트 + 순수 헬퍼
  (라벨/마커 칸 겹침 계산)와 그 단위 테스트(`timeline-layout.test.ts` 스타일).
- 타입체크는 worktree 내에서 `bun run typecheck`로 검증(서브모듈 변경 → 서브모듈 브랜치 `feat/F34`).
- 위험도 **낮음**: 표현 레이어/클릭 라우팅만, 주문·리스크 경로 무관. 롤백은 worktree 폐기로 즉시.

## 6. 범위 밖 (Out of scope)
- 같은 칸에 마커가 2개 이상 겹칠 때의 우선순위(기존 동작 그대로 둠).
- 라벨 위치/문구/색 변경, 타임라인 레이아웃·구간 계산 로직 변경.
- 마커가 라벨에 가려졌다는 별도 시각적 힌트(밑줄/색 변화) — 사용자가 "아예 안 가려도 좋다"고 함 → 불필요.

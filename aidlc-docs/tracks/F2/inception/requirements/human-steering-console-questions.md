## 의도 분석 (제가 이해한 내용 — 틀리면 바로잡아 주세요)

- **요청 유형:** 신규 기능 (사용자 대면).
- **목표:** AI와 사람이 함께 관리하는 트레이딩 시스템. 자율 에이전트(`main.py --mode agent`)는
  계속 돌아가되, 사람이 콘솔을 통해 자연어로 개입해서 조종할 수 있게 한다 (예: "AAPL 팔아").
  시스템은 (1) 사람의 의도를 **실행**하고, (2) 그 개입을 **영구적으로 기록**하며,
  (3) 돌아가는 에이전트가 **일관성**을 유지하도록 한다 — 즉 사람이 포지션을 바꿨다는 사실을
  에이전트가 **인지**해서 저널/테제(thesis)/보호주문이 어긋나지 않게 한다. 가장 핵심 가치로
  말씀하신 것: **AI의 실수를 자연어로 빠르게 바로잡는 것.**
- **범위:** 다중 컴포넌트 — `main.py`(연결), 신규 콘솔 모듈, `Journal`(영구적인 사람-개입 기록 +
  에이전트가 읽는 채널), `DecisionExecutor`(강제 실행 경로), 에이전트 프롬프트/오케스트레이터
  (개입 내용을 에이전트에게 다시 전달).
- **복잡도:** 중간~높음. 어려운 부분은 동시성(콘솔이 스케줄러 루프를 가진 라이브 데몬과 공존),
  강제 개입 후 에이전트의 멘탈 모델 일관성, 자연어 파싱, 강제 매매의 안전 게이트.

아래 질문들은 요구사항을 쓰기 전에 설계 분기점을 확정하기 위한 것입니다.

## 질문 1 — 콘솔은 라이브 에이전트 데몬과 어떤 방식으로 함께 동작해야 하나요?
`main.py --mode agent` 는 장시간 실행되는 프로세스(스케줄러 + `while True` 루프)이며,
백그라운드로 분리 실행(nohup / systemd / worktree 내부)될 수 있습니다. 콘솔이 이 데몬에
닿아야 합니다.

A) **별도 프로세스 + 파일 기반 IPC (권장)** — 새 진입점(예: `main.py --mode console` 또는
   서브커맨드)이 공유 저널/워크스페이스에 명령을 기록하고, 돌아가는 데몬이 이를 집어 처리한다.
   기존의 전면 파일 기반 설계와 잘 맞고, 데몬이 분리/헤드리스로 떠 있어도 동작한다.
B) **인-프로세스 REPL 스레드** — 콘솔이 `main.py --mode agent` 안에서 시작되는 stdin 스레드로,
   스케줄러와 객체를 직접 공유한다. 상태 공유는 가장 단순하지만 연결된 TTY가 필요하다
   (분리 실행된 데몬에는 부적합).
C) **둘 다** — 대화형으로 실행하면 데몬이 인-프로세스 콘솔을 띄우고, 동시에 별도 프로세스의
   파일 기반 명령도 받는다.
X) 기타 (아래 [Answer]: 태그 뒤에 설명)

[Answer]: B가 좋아보임. stdin을 생각하고 있었는데 혹시 내가 생각못한 큰 설계 어려움이 있다면 알려주길.

## 질문 2 — 콘솔은 사람이 입력한 내용을 어떻게 해석해야 하나요?
A) **정형 명령 문법만** — `sell AAPL`, `sell 50% TSLA`, `flatten AAPL`, `pause`, `note <텍스트>`
   같은 결정론적 동사. 경로에 LLM이 없어 가장 빠르고 안전하지만 문법을 익혀야 한다.
B) **LLM 자연어 파싱 → 정형 지시** — 자유롭게 입력("애플 던져, 곧 빠질 듯")하면 LLM이 정형
   명령으로 매핑. 가장 자연스럽지만 LLM 호출과 파싱 모호성 위험이 추가됨(질문 3의 확인으로 완화).
C) **하이브리드 (권장)** — 안전이 중요한 동작(매매, pause)은 정형 동사로, **그리고** 자유 형식의
   자연어 `note`/`intent` 줄은 기록 후 에이전트에 전달. 중요한 곳엔 결정론적 안전성을, 단순 맥락엔
   자유 텍스트를 제공.
X) 기타 (아래 [Answer]: 태그 뒤에 설명)

[Answer]: C가 좋겠다.

## 질문 3 — 스티어링 동작이 적용되기 전 확인/대화형 처리
(얼마나 대화형이어야 할지 확신이 없다고 하신 부분 — 바로 그 질문입니다.)

A) **즉시 실행(fire-and-forget)** — 파싱·기록 후 바로 실행, 확인 없음.
B) **해석 표시 + 확인 (권장)** — 콘솔이 해석한 내용을 다시 보여주고("해석: AAPL 100% 시장가 매도")
   매매는 y/n 확인을 기다린다. 노트/맥락은 확인 없이 적용.
C) **대화형 의도 수집** — 실행 전 콘솔이 짧게 "왜?"를 물어 근거를 함께 저장(더 풍부한 학습
   데이터)한 뒤 실행. 가장 무겁지만 말씀하신 학습 자료를 극대화.
X) 기타 (아래 [Answer]: 태그 뒤에 설명)

[Answer]: B로 가자.

## 질문 4 — v1에서 콘솔이 할 수 있어야 하는 동작 범위는?

## 질문 5 — *돌아가고 있는* 에이전트는 사람의 개입을 어떻게 인지하나요? (일관성의 핵심)
A) **수동 채널** — 개입을 전용 저널 파일(예: `human_directives.jsonl` + 마크다운 노트)에 기록하고,
   에이전트의 **다음 예약 턴** 프롬프트에 주입하여 그때 테제/노트를 재정렬하게 한다.
B) **수동 채널 + 즉시 재정렬 턴 (권장)** — A에 더해, 사람의 동작 직후 오케스트레이터가 별도
   "reconcile(재정렬)" 턴을 발생시켜 에이전트가 다음 크론 틱을 기다리지 않고 **지금** 저널/테제를
   갱신하게 한다.
C) **최소화 / 라이브 상태 의존** — 그냥 기록만 하고, 에이전트가 이미 매 턴 브로커 보유분을 다시
   읽으므로 바뀐 포지션을 암묵적으로 알아채게 둔다.
X) 기타 (아래 [Answer]: 태그 뒤에 설명)

[Answer]: B. agent가 관여 할 수 있는 파일이 많다보니 재정렬을 잘하는게 중요할듯

## 질문 6 — 사람이 강제한 매매도 에이전트 매매와 동일한 안전 게이트를 통과해야 하나요?
현재 모든 에이전트 주문은 RiskManager(브래킷/OCO 보호, 사이징, 서킷브레이커) → Broker 를 거칩니다.

A) **동일 게이트 (권장)** — 사람은 방향/종목/규모 의도를 정하되, 주문은 여전히
   RiskManager → Broker 를 거쳐 에이전트 매매와 동일하게 보호·일관성을 유지.
B) **브로커 직접** — 사람이 정확한 수량을 지정하고 최소 간섭으로 전송(이후 기록 + 보호는 적용),
   리스크 사이징은 우회.
C) **설정 가능** — 기본은 안전 게이트, 의도적으로 우회하고 싶을 때 명령별 "force raw"
   탈출구 제공.
X) 기타 (아래 [Answer]: 태그 뒤에 설명)

[Answer]: 응 동일 게이트로 하자.

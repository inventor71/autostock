# F103 구현·검증 계획

## 요구사항과 설계

1. 동일 배치의 부분 청산과 뒤따르는 보호 변경은 서로 다른 의도로 보존한다.
   같은 종류의 최신 지시는 이전 지시를 대체하고, 대체 사실도 감사 기록에 남긴다.
   미체결 청산을 보호 변경이 취소하지 않도록 주문 종료 후 남은 실제 수량을 보호한다.
   실패·재시작·부분 체결에서도 중복 청산이나 보호 수량 초과가 없어야 한다.
2. 체결은 기존의 신선한 종목별 호가와 실제 관측 시각만 사용한다.
   미체결 주문/큰 포지션을 우선 관측하고, 일부 오래된 응답은 한 번 제한적으로 재조회한다.
   원본 timestamp를 현재 시각으로 바꾸거나 동일 유동성을 재사용하지 않는다.
3. 전 종목의 엄격한 신선도와 평가액 기준의 데이터 커버리지를 별도 공개한다.
   작고 제한된 나이의 stale 잔고는 indicative로 표시하며 stale 종목의 체결은 계속 금지한다.
   큰/너무 오래된/실패한 평가 자료는 투자 판단을 보류한다. 원래 strict 통계를 덮어쓰지 않는다.
4. 초기 seed 수익과 관측 가능한 장중 구간 수익을 구분한다. 시드·기존 손익을 재작성하지 않는다.
5. 변경 지점과 실행 버전을 기록하고, 검증 후 Opus 재시작 및 Fable 예약 프로세스 갱신.

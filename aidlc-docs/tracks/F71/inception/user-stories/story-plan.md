# F71 — User Stories Part 1: 스토리 플랜

> 실행 근거(지능형 평가): 사용자 워크플로가 크게 바뀜(폰에서 운영) + 다중 컴포넌트(serve/PWA/
> MCP/WebAuthn) + 뮤테이팅 수용기준이 안전에 직결. → 실행 가치 충분.
>
> 질문 라운드 완료 (UAQ 2026-06-11, 4건):
> **홈=대시보드 우선** / **긴급정지 포함 모든 뮤테이팅 서명**(예외 없음, 일관성) /
> **TUI 세션 이어보기 시도**(feasibility 게이트 — serve와 TUI가 세션 저장소를 공유하는지
> Application Design에서 검증, 불가 시 '별도 대화' fallback) / **QR=URL+비번 모두**.

## 페르소나 (1)

**P1 — 운영자(개발자 본인).** autostock 데몬을 PC에서 돌리며, 외출/소파에서 폰으로 상태를 확인
하고 가끔 개입(승인 응답, 언락, 주문 취소, 긴급정지)한다. 기술 숙련자. 단일 사용자.

## 스토리 목록 (생성 예정)

| ID | 스토리 (요약) | FR 매핑 |
|----|--------------|---------|
| US-1 | 폰 1회 페어링 — PC QR(URL+비번) 스캔으로 서버 등록, 이후 자동 재접속 | FR-3, FR-4 |
| US-2 | 한눈 상태 확인 — **홈=대시보드**, 대화 없이 equity/포지션/health/대기승인 | FR-6 |
| US-3 | 추론 읽기 — 오늘 research/intraday 턴의 논지·결정 확인 | FR-7 |
| US-4 | 대화 개입 — 에이전트와 대화로 steer(언락/노트/디렉티브/answer) | FR-5 |
| US-5 | 안전한 개입 — **긴급정지 포함 모든 뮤테이팅**을 지문 서명 후 실행(예외 없음) | FR-8, FR-9 |
| US-6 | 상시 도달 — PC 부팅 후 별도 조작 없이 폰에서 항상 접속 가능 | FR-1, FR-2 |
| US-7 | 안전 실패 — tailnet 밖/비번 오류/서명 실패 시 명확히 거부·표시 | NFR-1, NFR-4 |
| US-8 | (feasibility-게이트) TUI 세션 이어보기 — PC에서 하던 대화를 폰에서 열람/이어가기. 설계 단계 검증 후 불가 시 '별도 대화 + 데몬 상태 공유'로 fallback | 신규 FR-10 |

각 스토리는 **수용 기준(AC)** 포함해 Part 2에서 생성. US-5/US-7의 AC가 Security Baseline 검증
항목과 1:1 매핑되도록 작성한다(예: "서명 없는 뮤테이팅 요청은 서버가 거부한다").

## 1. Intent Analysis

### 1.1 사용자 의도 흐름 (직전 토론, UAQ)
1. F64 = "프롬프트 자가재작성" 선택 (가장 공격적 옵션).
2. 교체 방식 = **"즉시 교체(완전 자동)"** 선택 (사람 게이트 없음).
3. 이후: *"너무 aggressive 하게 교체하는걸 원하지 않으니 자기발전 프롬프트에 대한 불변
   가이드라인을 만들어서 넣자. 이 또한 내 승인을 받도록해"* → **불변 헌장** 도입.
4. 승인 범위 = **"헌장 변경만 승인, 교체는 자동"** 선택.
5. 헌장 목적 정정: *"agent 자가개선의 퀄리티가 나빠지기 막기위한 헌장임. 헌장에 코드에서 강제된
   내용을 굳이 적을 필요 없음."* → 헌장에서 실행-안전 규칙 제거, 품질 규율만.
6. *"5번은 너무 강력함. gradual change를 권장하게 하자."* → 원칙5 금지→권장.

### 1.2 핵심 의도
에이전트가 자기 메트릭(F62)으로 가이던스를 **자동 진화**하되, **불변 헌장**이 진화의 품질
하한을 지키고, **사람은 헌장(경계)만** 통제한다. 진화 자체는 헌장 컴플라이언스+롤백+변경량
캡으로 통제하며 매 교체에 사람을 부르지 않는다.

### 1.3 요청 유형
- **Type**: Agent self-improvement engine (high-risk)
- **Scope**: 신규 constitution + self-rewrite 모듈, prompts.py 2층 조립, prompt_manager 재사용,
  EOD 재작성 스텝, 자동 롤백.
- **Complexity**: Complex (자기수정 루프; 단 불변 경계로 안전 격리)

## 3. Functional Requirements

### FR-1: 2층 프롬프트
- **FR-1.1** 가이던스 프롬프트는 [불변 헌장] + [진화 가능 가이던스] 2층으로 조립된다.
- **FR-1.2** 헌장은 `src/agent/constitution.py`의 `AGENT_CONSTITUTION` 단일 상수로 존재하며,
  에이전트가 편집하는 `workspace/`에 두지 않는다 (write 불가).
- **FR-1.3** 진화 섹션만 자가재작성 대상. 헌장은 항상 진화 섹션 위에 prepend된다.
- **FR-1.4** (critic HIGH#3) 진화 가이던스를 **workspace `CLAUDE.md`에서 들어내** Python 관리
  저장소로 옮긴다 (CLAUDE.md는 에이전트가 직접 편집 가능 → 게이트 우회 가능하므로). 에이전트는
  EOD에 새 텍스트를 **제안**만 하고 직접 쓰지 않으며, Python이 검증·영속·prepend한다. CLAUDE.md엔
  정적 역할+decision 스키마만 남긴다(진화 휴리스틱 단일 출처화).
- **FR-1.5** `build_guidance()`는 가이던스 필요 빌더(morning/intraday/wake/multi_research)에만
  주입; 평가턴·**EOD 자기재작성 턴 제외(재귀 방지)**.

### FR-2: 헌장 (Constitution) — 내용
- **FR-2.1** 헌장은 **품질 규율 6원칙**만 담는다 (전문: `functional-design/constitution.md`):
  ① 정직성/anti-Goodhart ② 증거기반(노이즈 배제) ③ 레짐 과적합 방지 ④ 검증된 것 보존
  ⑤ 점진성 **권장** ⑥ 구체성.
- **FR-2.2** 코드가 이미 강제하는 실행-안전(자문전용/스탑/리스크한도/유니버스·ETB/스키마)은 헌장에
  포함하지 않는다 (방어는 코드; 헌장은 품질 메아리 아님).

### FR-3: 자가재작성 (EOD, 자동)
- **FR-3.1** EOD에 에이전트가 F62 효능 메트릭을 보고 진화 섹션의 새 버전을 생성한다.
- **FR-3.2** 새 버전은 PromptVersion으로 lineage(parent_version) 기록된다 (prompt_manager 재사용).
- **FR-3.3** 새 버전은 **컴플라이언스 검증(FR-4)** 통과 시에만, 그리고 **변경량 캡/쿨다운(FR-6)**
  충족 시에만 **즉시 교체**되어 다음 턴부터 사용된다.

### FR-4: 컴플라이언스 검증 (결정론 게이트, 진화 섹션 대상)
- **FR-4.1 (모순 스캔/denylist)** 진화 섹션이 헌장을 무력화하려는 패턴(주문권 주장/스탑 회피/
  리스크 우회/유니버스·ETB 위반)을 매치하면 거부.
- **FR-4.2 (인젝션 자기방어)** 진화 섹션이 헌장을 무시/무력화하라는 메타지시(`ignore the rules
  above` 등)나 새 헌장 헤더 주입을 시도하면 거부.
- **FR-4.3 (구조 바운드)** 헌장 바이트 해시 불변 확인; 진화 섹션 diff ≤ 변경량 캡; 총길이 ≤ 상한.
- **FR-4.4 (Fail-closed)** 검증 실패 시 새 세대를 **거부하고 이전 버전 유지**, lineage 감사에
  거부 사유 기록, steering 이벤트로 운영자에 "self-rewrite rejected: <사유>" 통지.

### FR-5: 자동 롤백
- **FR-5.1** `prompt_version`별 라이브 메트릭(F62)을 추적한다.
- **FR-5.2** 새 버전이 채택 후 N일(설정) 동안 parent 대비 **벤치마크 초과수익(excess)** 기준으로
  악화하면 자동으로 parent 버전으로 복귀한다.
- **FR-5.3** 다세대 누적 드리프트 방지: 주기적으로 **원본 시드 가이던스 대비 회귀 비교**(전체
  lineage가 한 방향으로 표류했는지 점검) 리포트.

### FR-6: 변경량 캡 / 댐핑
- **FR-6.1** 세대당 진화 섹션 변경량(diff)에 상한.
- **FR-6.2** 쿨다운: 매일 재작성하지 않는다 (설정 주기).
- **FR-6.3** F62 통계 가드(min_sample/지속성) 미충족 시 재작성 보류.

### FR-7: 헌장 변경 승인 메커니즘
- **FR-7.1** `AGENT_CONSTITUTION`의 해시를 핀으로 박는 **고정 체크섬 테스트**를 둔다.
- **FR-7.2** 헌장이 바뀌면 테스트가 실패 → 사람이 핀 해시를 의도적으로 갱신해야 통과. 그 커밋이
  곧 **사용자 승인 행위**. 우발적·프로그램적 헌장 변경은 차단된다.

## 4. Non-Functional Requirements
- **NFR-1 (불변 경계)**: 자가재작성은 프롬프트 텍스트만. executor/RiskManager/스키마는 코드 불변.
- **NFR-2 (Fail-closed)**: 컴플라이언스 검증·롤백 판정은 의심 시 안전측(거부/복귀).
- **NFR-3 (결정론 격리)**: 검증·lineage·롤백 판정은 순수·단위테스트. 비결정은 LLM 재작성 1스텝.
- **NFR-4 (감사성)**: 모든 세대·거부·롤백을 lineage에 전수 기록.
- **NFR-5 (0 new deps)**: prompt_manager/기존 자산 재사용.

## 5. 검증 기준 (Acceptance)
1. 헌장 바이트 1비트 변경 → 고정 체크섬 테스트 실패 (FR-7).
2. 주문권 주장/스탑 회피/인젝션 문구를 담은 진화 섹션 → 컴플라이언스 거부 + 이전 버전 유지 (음성).
3. 합성으로 parent 대비 excess 악화 버전 → N일 후 자동 롤백 (FR-5).
4. 변경량 캡 초과 diff → 거부 (FR-6).
5. 정상 진화(소폭·헌장 준수) → 즉시 교체되어 다음 턴에 반영, lineage 기록.
6. 전체 pytest green, 0 new deps. (F62/F65 선행 머지.)

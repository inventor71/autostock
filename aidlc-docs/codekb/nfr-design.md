# NFR Design

## Resilience
| Pattern | Implementation | Location |
|---|---|---|
| Torn-read-safe append | `read_complete_lines` consumes only newline-terminated lines and persists a byte cursor (`ByteCursor`); a truncated/rotated file resets the cursor rather than erroring | `src/core/jsonl.py` |
| Atomic in-place rewrite | Write to a unique temp file (pid+uuid) in the same directory, then `os.replace` — readers never observe a torn write | `src/core/jsonl.py` (`atomic_write_text`), used for `.executor_state.json`, position theses, `steering/snapshot.json`, `steering/quotes.json` (F95), `steering/codebase.json`, trigger specs |
| Stat-stable read (non-atomic writer) | Console reads a file between two `stat()` snapshots and retries (max 5) if size/mtime changed mid-read, to tolerate the agent's non-atomic `claude` CLI Write tool | `operator-console/src/filedrop.ts` (`readThesis`) |
| Idempotent decision execution | Byte cursor + terminal-index set in `.executor_state.json`; terminal indices are never reprocessed even across a crash/restart | `src/agent/executor.py` |
| Idempotent fills | Wake detection keys on the broker's fill/activity id — one wake per `fill_id` | `src/agent/intraday/records.py` (`FillEvent`) |
| Idempotent steering commands | Day-scoped persisted processed-id set dedupes replayed/duplicated commands | `src/agent/steering/channel.py` |
| Event coalescing with bounded loss | Intraday wake events are buffered and fired as one turn; if the turn times out, buffered events are dropped (safety over data loss) rather than retried indefinitely | `src/agent/intraday/wake.py` |
| Off-hours command queuing | Human trade commands issued while the market is closed are parked in `pending_human_trades.jsonl` and drained at the next open | `src/agent/trading/modes/agent.py` / steering runtime |
| HTTP timeout bounds | Explicit connect/read timeouts installed on both Alpaca clients (TradingClient, StockHistoricalDataClient) and the KIS REST client, so a stalled socket can never wedge the daemon's scheduler thread; health-check LLM probes additionally pin `timeout=10, max_retries=0` so a hung provider can't stall the health cycle | `src/execution/brokers/alpaca_broker.py`, `src/execution/brokers/kis/rest.py`, `src/monitoring/health/dimensions/llm.py` |
| Rate limiting / throttling | KIS REST client serializes requests to a configurable per-second cap; StockTwits sweep enforces an hourly request budget and aborts the tick on a `RateLimited` exception | `src/execution/brokers/kis/rest.py`, `src/signals/sources/stocktwits.py` |
| Bounded-concurrency price fetch | Latest-price fetch across a universe uses a fixed 8-worker thread pool; one symbol's failure yields `{symbol: None}` without affecting the rest | `src/data/prices.py` (`fetch_latest_prices`) |
| Cache-only scheduler reads | The 5s `WakeDetector` tick reads only cached bars/prices, never a synchronous broker fetch, so a slow broker call can never delay the daemon's core loop | `src/agent/intraday/wake.py`, `bars.py` |
| Health-check isolation | Each dimension checker (broker/risk/account/llm/config_env/...) runs independently in a thread pool via `CheckerDispatcher`; one checker's exception degrades only its own dimension, never the whole report | `src/monitoring/health/checker.py` |
| Multi-provider health probing | `LLMChecker`/`ConfigEnvChecker` check every distinct LLM provider actually in use (the trading `llm.provider` plus a possibly-different `agent.provider`) rather than assuming a single provider, and the API probes retrieve model metadata only — they no longer spend a generation call just to prove connectivity | `src/monitoring/health/dimensions/llm.py`, `src/monitoring/health/dimensions/config_env.py` |
| LLM retry with fail-fast on bad output | `_retry_with_backoff` retries transient transport exceptions with exponential backoff, but a `ValueError` (incomplete/empty model output, e.g. `stop_reason != "end_turn"` or a non-`completed` Responses status) is raised immediately and never retried — an invalid answer is a correctness problem, not a transient one | `src/strategy/llm/client.py` |
| Benchmark baseline isolation | Each shadow-baseline strategy runs its own `TradingEngine`; one baseline's exception is caught per-tick and never breaks the others or the live agent loop | `src/benchmark/runner.py` |
| Daemon health/wedge detection | The console launcher watches `snapshot.json`'s `published_at` for staleness (45s window); if wedged, it waits with patience for slow LLM turns, then auto-restarts the daemon once | `operator-console/launcher/daemon.ts` |
| Circuit breaker (market-wide halt) | SPY day-change is checked each tick and updates two independent breakers — one halts new long entries below a threshold, the other halts new shorts above a threshold; existing positions are unaffected, only new entries are gated | `src/risk/manager.py` (`market_halt_threshold_pct`, `short_market_halt_threshold_pct`) |
| Execution drift guard (fail-closed fill cap) | A momentum entry that would otherwise be a MARKET order is downgraded to a capped LIMIT if price has moved adversely past the decision anchor (LLM entry, or the price stamped at decision time) by more than a configurable ATR multiple — bounding worst-case fill price against research→execution lag; a runaway name simply doesn't fill rather than filling at an arbitrarily bad price | `src/risk/manager.py` (`entry_drift_guard_atr`, `_drift_guard_band`) |
| Fail-honest signal sources | A signal source that errors returns an explicit error annotation rather than a silently empty/default result; the failure is surfaced in `degraded_sources` so the LLM's prompt context states which sources are missing instead of presenting a falsely-complete brief | `src/signals/collector.py`, `src/signals/brief.py` |
| Fail-honest derived metrics | Read-time derivations over existing logs (e.g. agent-vs-SPY performance headline) return `None` on missing/short/non-positive input rather than fabricating a number; downstream publishers fold the `None` in additively instead of guessing | `src/agent/logs/performance.py` (`compute_performance`) |
| Durable client-side order intent (Toss) | `TossClient.create_order` persists `{clientOrderId → fingerprint, submitted_at, response}` to a locked local file *before* the HTTP POST; a crash mid-flight blocks resubmission under the same id until reconciled, a replayed identical payload returns the cached response, and a changed payload under a reused id is rejected — idempotency without relying on the broker API itself being retry-safe | `src/execution/brokers/toss/client.py` (`create_order`) |
| GET-retries / POST-never-retries split (Toss) | GET requests retry up to 3x with exponential backoff (honoring `Retry-After`, capped at 5s); POST (order-mutating) requests never auto-retry — idempotency instead comes from the durable intent ledger above | `src/execution/brokers/toss/client.py` (`request`) |
| Fail-closed fee/commission staleness (Toss) | `CommissionSchedule` fails closed (raises) if zero or more than one commission rate matches the market+date; `TossCosts.profile()` raises outside its hardcoded Q4-2026 assumption-review window rather than silently pricing fills with an expired fee schedule | `src/execution/brokers/toss/costs.py` |
| Quote-quality gated execution (Toss shadow) | New BUY decisions are blocked (not existing exits) when <99% of portfolio value is backed by a fresh (≤120s) quote; a stale/missing book degrades the shadow account's own self-reported health rather than silently trading on data it can't trust | `src/execution/brokers/toss/quality.py`, `src/evals/toss_shadow.py` (`ShadowExecutor`) |
| Persistent retry with exponential backoff (Toss shadow decisions) | A decision that fails to execute is retried at `min(300s, 30 * 2^min(attempts-1,4))` intervals rather than every poll tick or never; cleared on success or decision expiry | `src/evals/toss_shadow.py` (`ShadowExecutor._record_retry`) |
| Durable decision→order identity (Toss shadow) | Shadow decisions are keyed by a hash of decision index + content, so a daemon crash/restart recovers the same order via the durable ledger instead of resubmitting a duplicate | `src/evals/toss_shadow.py` (`ShadowExecutor.execute_decision`) |
| Fail-honest news fetch (F105) | A news-provider exception becomes an explicit `NewsResult(status="unavailable", errors=[...])` rather than a silently-empty list indistinguishable from "no news"; a fallback provider is only consulted on empty/stale primary results and never relabels old content as fresh | `src/data/news.py` (`fetch_news`, `FallbackNewsProvider`) |
| Source-vs-retrieval timestamp separation (F105) | Every quote/bar/news fact keeps the provider's native `source_as_of` strictly separate from `retrieved_at`; a cache hit never updates `source_as_of` to "now," so staleness checks downstream (drift guard, quote quality, news freshness) can't be fooled by re-fetch cadence | `src/data/freshness.py` |

## Scalability
| Pattern | Implementation | Location |
|---|---|---|
| Backtest fast-path precompute | Strategies that support `supports_precompute()` and don't need dynamic per-bar selection get O(1) indicator lookups instead of an O(n²) per-bar recompute/copy | `src/backtest/engine.py` |
| Parallel parameter search | Grid-search parameter optimization runs each parameter combination in a separate process via `ProcessPoolExecutor`, isolating strategy state per worker | `src/backtest/optimizer.py` |
| Multi-instance production isolation | `COMPOSE_PROJECT_NAME=autostock-<name>` namespaces containers/volumes/networks so N daemon instances run concurrently on distinct accounts/workspaces without collision; shared verify image and `node_modules` volumes avoid per-instance rebuild/reinstall cost | `docker-compose.prod.yml`, `scripts/prod-run.sh` |
| Signal brief caching | Research-turn brief is TTL-cached by `(today, horizon_days, ipo_horizon_days, held_set)`; sentiment outliers additionally cached 300s; news cached 15 min per symbol | `src/signals/collector.py`, `src/signals/sentiment.py`, `src/data/providers/news_provider.py` |
| Universe snapshot caching | The tradeable-symbol universe is cached with a 1-day TTL and an atomic on-disk snapshot, avoiding a Wikipedia/KIS re-fetch on every process restart | `src/universe/base.py` |
| Warm quote cache for UI click-through | An in-memory `QuoteBook` keeps a capped (30), TTL'd (10s) set of "candidate" symbols (held ∪ resting-order ∪ recently decided/intervened) refreshed on a short cadence via the shared data provider and published to `steering/quotes.json`, decoupled from the 5s snapshot cadence | `src/agent/steering/quotes.py`, `src/agent/steering/channel.py` (`publish_quotes`) |
| Health-check parallelism | `CheckerDispatcher` runs all dimension checks concurrently (default 6 workers) rather than sequentially | `src/monitoring/health/checker.py` |
| Commission/rate caching (Toss) | Live-fetched commission rate cached 6h, expiring at KST midnight, avoiding a fetch on every order/fill | `src/execution/brokers/toss/costs.py` (`CommissionSchedule`) |
| Bounded Toss market-data request rate | Shadow polling and the data provider stay within the public 15 req/s Toss market-data cap rather than hammering the API every tick | `src/execution/brokers/toss/shadow.py`, `src/data/providers/toss_provider.py` |

## Security
| Pattern | Implementation | Location |
|---|---|---|
| Layered defense-in-depth (console) | (1) side-effect tools compile-time-removed under lockdown, (2) default-deny permission profile, (3) opencode's core MCP auto-gating (`ask` before every mutating tool), (4) HMAC token validation on every steering command, (5) WebAuthn passkey gate for remote mutating commands | `operator-console/cli/packages/opencode/src/tool/registry.ts`, `cli/opencode.json`, `session/tools.ts`, `src/agent/steering/`, `server/autostock/webauthn.ts` |
| Constant-time token validation | The shared steering operator token is compared in constant time to avoid timing side-channels | `src/agent/steering/channel.py` |
| Secrets never logged / never propagated to subagent | Steering token, KIS appkey/appsecret, and account ids are excluded from all logs/events; `SteeringCommand.redacted()` strips the token before serialization; benchmark equity snapshots mask account ids (`account_masked`); `scrub_agent_env` removes the operator token from the environment dict before spawning the trading agent subprocess | `src/agent/steering/records.py`, `src/benchmark/models.py`, `src/agent/steering/security.py` (`scrub_agent_env`) |
| Remote-vs-local trust boundary | The console classifies a request as in-process / host-local-loopback / remote; only remote mutating requests require a WebAuthn passkey assertion — host access is the trust boundary | `operator-console/cli/packages/opencode/src/server/autostock/webauthn.ts` |
| Symbol/input validation | StockTwits symbol input validated against a strict regex before URL construction; structured order args validated with zod (console) then Pydantic `extra="forbid"` (daemon) | `src/signals/sources/stocktwits.py`, `operator-console/src/mcp-server.ts` |
| LLM parameter input validation | `reasoning_effort` is validated against a fixed allow-list (`low/medium/high/xhigh/max`) at client construction and raises `ValueError` immediately on an unrecognized value, rather than forwarding an attacker/misconfig-controlled string to the provider API | `src/strategy/llm/client.py` (`BaseLLMClient.__init__`) |
| Secret scanning in CI/pre-commit | gitleaks runs as a pre-commit hook with an explicit allowlist for `.env.example` templates and test fixtures | `.pre-commit-config.yaml`, `.gitleaks.toml` |
| Fail-closed provider routing | An unrecognized `broker.provider`/`data.provider` raises loudly rather than silently falling back to a default | `src/execution/brokers/factory.py` |
| Non-root container runtime | Production/verify containers run as the host's `${DOCKER_UID}:${DOCKER_GID}`, so bind-mount writes are host-owned from the start (no root-owned artifacts, no `sudo` needed for worktree cleanup) | `docker-compose.prod.yml`, `docker-compose.verify.yml`, `scripts/verify-run.sh` |
| Prod-safety preflight | The verify harness refuses to run unless `AUTOSTOCK_ENV_FILE` is set and exists, and refuses if a real `/app/.env` differs from `.env.test` — preventing an accidental prod-account test run | `scripts/verify.sh` |
| Agent lockdown | `AUTOSTOCK_LOCKDOWN=on` removes all write/exec-capable tools from the agent's toolset entirely (not just permission-gated) in production and verify-attach; an optional `AUTOSTOCK_SUPERVISOR=on` widens read-only access to the whole repo (excluding secrets/logs/.git) for human debugging sessions | `docker-compose.prod.yml`, `operator-console/launcher/config.ts` |
| Shorting master switch | `shorting_enabled` is a constructor-level master switch independent of per-symbol short config; the deployed default is off unless explicitly enabled, keeping short-selling an opt-in safety control | `src/risk/manager.py` (`RiskManager.__init__`) |
| Toss credential storage outside the repo, user-only | Toss credentials/tokens/commission cache/order-intent ledger live under `~/.config/autostock/toss/` and `~/.local/state/autostock/toss/` (never inside the repo), written 0600 with `fcntl` locks and `O_NOFOLLOW` reads (no symlink following) | `src/execution/brokers/toss/storage.py`, `credentials.py` |
| Toss read-only-by-default + shared-token forced read-only | `TossClient`/`TossBroker` default to read-only; a shared-token credential (reusing the external `toss-stock` app's token) cannot be constructed in write-enabled mode at all — enforced at `__init__`, not just at call time | `src/execution/brokers/toss/client.py` (`__init__`) |
| Toss write-path double gate (config + app mode) | A live, order-mutating `TossBroker` requires both `toss.read_only=false` AND `app.mode=live`; either alone leaves the broker read-only | `src/execution/brokers/toss/broker.py` (`_write_enabled`), `factory.py` |
| News error detail scrubbed to exception type | `NewsResult.errors` records exception *types*, not raw exception text, so a provider error can't leak credentials/URLs embedded in its message into logs or the LLM prompt | `src/data/news.py` (`fetch_news`) |

## Observability
| Pattern | Implementation | Location |
|---|---|---|
| Structured health reporting | `HealthReport` aggregates per-dimension `CheckResult`s with severity ordering (OK < SKIPPED < WARNING < ERROR < CRITICAL) and maps to a shell exit code for CI/cron use; the `llm` and `config_env` dimensions now report per-provider detail when the trading and agent LLM providers differ | `src/monitoring/health/report.py`, `src/monitoring/health/dimensions/llm.py`, `src/monitoring/health/dimensions/config_env.py` |
| Live account/portfolio snapshot | The daemon publishes an atomic `steering/snapshot.json` on every cycle (account, positions, orders, pending approvals, health, agent activity), plus a separate `steering/quotes.json` warm-quote feed on its own cadence, consumed by the console sidebar and the mobile dashboard | `src/agent/steering/` publisher, `src/agent/steering/quotes.py`, `operator-console/cli/.../autostock/dashboard-read.ts` |
| Turn/decision audit trail | Every agent turn is logged under `workspace/turns/<TURN_ID>/` (research prompt, intraday brief, etc.) alongside `turns.jsonl` metadata, enabling `/agent-trace` and `/why` console introspection | `src/agent/logs/turn.py`, console `steer_read` tools |
| LLM usage/completion telemetry | Each provider client records `last_usage` (model, token usage) and raises on an incomplete/truncated response (non-`end_turn` stop reason, non-`completed` Responses status, or empty text) so silent truncation is observable rather than returned as a seemingly-valid answer | `src/strategy/llm/client.py` |
| Agent-vs-benchmark performance scorecard | Read-time join of the existing equity log's account equity and SPY mark into a single cumulative-return-vs-SPY headline (plus alpha and day delta), computed fail-honest (`None` on insufficient data) and folded additively into the snapshot/dashboards without a new persisted log | `src/agent/logs/performance.py` |
| Shadow-benchmark comparison | Continuous LLM-vs-deterministic-baseline equity comparison gives a standing signal on whether the LLM PM is adding value over simple strategies | `src/benchmark/` |
| Degraded-source visibility | Signal collection surfaces exactly which research sources failed (`degraded_sources`) directly in the LLM's prompt context, rather than silently omitting sections | `src/signals/collector.py`, `src/signals/brief.py` |
| Research-mode comparison harness | A local, append-only experiment harness runs the same frozen research scenarios across production modes/models/repeats and aggregates behavior-and-schema pass rate, error/failed-call/permission-denial counts, executor-replay gate issues, latency, and token/cost means into a per-experiment `summary.csv` and a human-readable `summary.md` — a model/prompt-change evaluation signal distinct from (and explicitly disclaiming) a trading-returns backtest | `src/evals/compare_research.py`, `src/evals/returns.py` |
| Research-data-gap reporting (F105) | A dedicated, explicitly-labeled "last intraday context, not process health" report distinguishes news/price/bar coverage gaps, stale/unparseable quote timestamps, un-refreshed watchlist symbols, and account-snapshot errors from general process health, so a data-quality problem is never diluted into (or confused with) the broker/risk/LLM health dimensions | `src/monitoring/research.py` (`read_context_summary`) |
| Shadow account health/quality telemetry (Toss) | Each shadow poll reports an explicit health status (ok/degraded/blocked/error/ended) plus quote-quality metrics (fresh-value %, stale/unavailable symbols) and session performance (net/hold return, peak equity, max drawdown, fill count) appended to `equity.jsonl` | `src/execution/brokers/toss/shadow.py` (`poll`, `_report`), `quality.py` |
| Per-symbol source timestamp in the prompt (F105) | The research brief renders each price's `source_as_of` inline (e.g. `[daily source=2026-11-25T16:00]`) so the LLM sees provenance, not just a number, for every mover/alert | `src/signals/collector.py`, `src/signals/records.py` (`price_source_times`) |
